---
title: "Get Order Status"
---

The **Order Status** (`/v2/order/command` with `transactionType: "STATUS"`) endpoint is used by merchants to fetch the real-time status and payment history of an existing order. This server-to-server API allows your backend to verify order settlement, capture UTR/bank references, and reconcile payment attempts before fulfilling customer orders.

---

| **Environment** | **HTTP Method** | **API** |
| :-- | :-- | :-- |
| `Sandbox` | `POST` | [https://api-uat.originpay.in/v2/order/command](https://api-uat.originpay.in/v2/order/command) |
| `Production` | `POST` | [https://api.originpay.in/v2/order/command](https://api.originpay.in/v2/order/command) |

## 1. Endpoint Details

| Attribute | Value |
| --- | --- |
| **URL** | `/v2/order/command` |
| **Method** | `POST` |
| **Content-Type** | `application/json` |
| **Authentication** | Basic Token (Authorization Header) |

---

## 2. Required Headers

| Header | Value | Description |
| --- | --- | --- |
| `Authorization` | `Basic <basic_token>` | Basic token generated from `/v2/auth/token` or `base64(public_key:secret_key)` |
| `X-MERCHANT-ID` | `<your_merchant_id>` | Unique merchant identifier |
| `Content-Type` | `application/json` | Required for JSON request bodies |

---

## 3. Request Body

The status inquiry request must be sent in JSON format.

### Request Fields

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `merchantOrderId` | string | Yes | Unique order ID sent when creating the order (`merchant_order_id` is also accepted) |
| `amount` | number | Yes | Original order amount in paise (1 INR = 100 paise). Must match the order amount |
| `transactionType` | string | Yes | Must be `"STATUS"` (`transaction_type` is also accepted) |

---

## 4. Request Example

```json
{
  "merchantOrderId": "ORDER12345",
  "amount": 50000,
  "transactionType": "STATUS"
}
```

### Order Created (Payment Not Initiated Yet)

**Status Code:** `200 OK`

```json
{
  "success": true,
  "statusCode": 200,
  "txnStatus": "CREATED",
  "message": "Order created, payment not initiated yet",
  "data": {
    "merchant_order_id": "ORDER12345",
    "order_id": "ord_100000045",
    "attempt_id": null,
    "amount": 50000,
    "currency": "INR",
    "order_status": "created"
  }
}
```

---

## 6. Transaction Status Mapping

The top-level `txnStatus` field reflects the overall status of the latest payment attempt:

| `txnStatus` | Internal Status | Meaning |
| :-- | :-- | :-- |
| `SUCCESS` | `success` | Payment was authorized and captured successfully. Fulfill the order. |
| `FAILED` | `failed` | Payment attempt failed or was declined by the bank. |
| `EXPIRED` | `expired` | The payment session or checkout link expired before completion. |
| `CANCELLED` | `cancelled` | The transaction was cancelled by the user. |
| `CREATED` | `created` | The order was created, but no payment attempt has been made yet. |
| `PENDING` | `pending` | Payment is currently being processed by the bank or gateway. |

---

## 7. Implementation Example

### JavaScript (Fetch)

```javascript
const requestBody = {
  merchantOrderId: "ORDER12345",
  amount: 50000,
  transactionType: "STATUS"
};

const response = await fetch("https://api.originpay.in/v2/order/command", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "Authorization": "Basic YOUR_BASIC_TOKEN",
    "X-MERCHANT-ID": "YOUR_MID"
  },
  body: JSON.stringify(requestBody)
});

const result = await response.json();
```

---

## Important Notes

- The `amount` provided in the request must match the exact amount the order was created with, specified in paise.
- An order can contain multiple attempts in `paymentDetails` if the customer made multiple tries. The attempts are returned in descending chronological order.
- Always check `txnStatus === "SUCCESS"` before provisioning services or marking orders as paid.
