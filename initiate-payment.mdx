---
title: "Initiate Payment"
---

The **Standard Checkout** endpoint is used to create a payment session and generate a secure checkout link for your customers. This endpoint requires a valid Basic token and merchant identification.

---

| **Environment** | **HTTP Method** | **API** |
| :-- | :-- | :-- |
| `Sandbox` | `POST` | [https://api-uat.originpay.in/v2/checkout/pay](https://api-uat.originpay.in/v2/checkout/pay) |
| `Production` | `POST` | [https://api.originpay.in/v2/checkout/pay](https://api.originpay.in/v2/checkout/pay) |

## 1. Endpoint Details

| Attribute | Value |
| --- | --- |
| **URL** | `/v2/checkout/pay` |
| **Method** | `POST` |
| **Content-Type** | `application/json` |
| **Authentication** | Basic Token (Authorization Header) |

---

## 2. Required Headers

| Header | Value | Description |
| --- | --- | --- |
| `Authorization` | `Basic <basic_token>` | Basic token generated from `/v2/auth/token` or `base64(public_key:secret_key)` |
| `X-MERCHANT-ID` | `<your_merchant_id>` | Unique merchant identifier |

### Optional Headers

| Header | Value | Description |
| --- | --- | --- |
| `X-SOURCE` | `API` / `SDK` / `CHECKOUT` / `PAYMENT_LINK` | Request origin source (Default: `API`) |
| `X-SOURCE-CHANNEL` | `web` / `android` / `ios` | Request channel platform (Default: `web`) |
| `X-BROWSER-FINGERPRINT` | string | Optional client browser fingerprint |
| `X-MERCHANT-APP-ID` | string | Optional merchant application identifier |

---

## 3. Request Body

The request must be sent in JSON format.

### Core Fields

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `amount` | number | Yes | Amount in paise (1 INR = 100 paise). Range: 1 to 1,000,000 (Whole integer only) |
| `currency` | string | No | Currency code. Allowed: `"INR"`. Default: `"INR"` |
| `merchantOrderId` | string | Yes | Unique order ID from your system. Alphanumeric only (`^[a-zA-Z0-9]+$`) |
| `expireAfter` | number | No | Expiry time in seconds (300–900). Default: 300 |
| `customer` | object | Yes | Customer identity information |
| `paymentInfo` | object | Yes | Payment configuration and redirect details |
| `paymentHandler` | object | Yes | Must be `{ "type": "STANDARD" }` |

---

### customer Object

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `name` | string | Yes | Full name of the customer (max 255 characters) |
| `email` | string | Yes | Valid email address (max 255 characters) |
| `phone` | string | Yes | Mobile number (max 15 characters) |

---

### paymentInfo Object

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `redirectUrl` | string | Yes | Valid URL where user is redirected after payment |
| `remark` | string | Yes | Transaction note or purpose (max 255 characters) |
| `methods` | array | No | Allowed: `upi`, `card`, `netbanking`, `wallet` (Defaults to all) |

---

### Custom Fields

- You can pass up to **5 additional fields** at the root level
- Keys must match `^[a-zA-Z0-9_]{1,25}$` (max 25 characters)
- Values must be strings (max 25 characters)

---

## 5. Implementation Example

### JavaScript (Fetch)

```javascript
const requestBody = {
  amount: 50000,
  currency: "INR",
  merchantOrderId: "ORDER12345",
  expireAfter: 600,
  customer: {
    name: "John Doe",
    email: "john@example.com",
    phone: "9876543210"
  },
  paymentInfo: {
    methods: ["upi", "card", "netbanking", "wallet"],
    remark: "Subscription Payment",
    redirectUrl: "https://yourwebsite.com/callback"
  },
  paymentHandler: {
    type: "STANDARD"
  },
  udf1: "Additional Info 1",
  udf2: "Additional Info 2",
  udf3: "Additional Info 3",
  udf4: "Additional Info 4",
  udf5: "Additional Info 5"
};

const response = await fetch("https://api.originpay.in/v2/checkout/pay", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "Authorization": "Basic YOUR_BASIC_TOKEN",
    "X-MERCHANT-ID": "YOUR_MID"
  },
  body: JSON.stringify(requestBody)
});

const result = await response.json();
```

---

## Important Notes

- Ensure `merchantOrderId` is unique for every request and contains only alphanumeric characters.
- Amounts must always be integers specified in paise (e.g. ₹500.00 = `50000`).
- The generated `payment_url` is single-use and expires according to `expireAfter`.
- Always verify payment status via server-to-server Order Command API or webhooks; do not rely solely on frontend redirection for fulfillment.
