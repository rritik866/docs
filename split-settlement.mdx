---
title: "Split Settlements"
---

The **OneSplit Payment API** is an extension of the One Checkout endpoint (`POST /v2/onecheckout/pay`) that allows platforms, marketplaces, and aggregators to accept a single customer payment and programmatically allocate settlement funds to a designated Originpay sub-account (`originpay_sub_acc_id`).

---

| **Environment** | **HTTP Method** | **API** |
| :-- | :-- | :-- |
| `Sandbox` | `POST` | [https://api-uat.originpay.in/v2/onecheckout/pay](https://api-uat.originpay.in/v2/onecheckout/pay) |
| `Production` | `POST` | [https://api.originpay.in/v2/onecheckout/pay](https://api.originpay.in/v2/onecheckout/pay) |

## 1. Endpoint Details

| Attribute | Value |
| --- | --- |
| **URL** | `/v2/onecheckout/pay` |
| **Method** | `POST` |
| **Content-Type** | `application/json` |
| **Authentication** | Basic Token (Authorization Header) |

---

## 2. Required Headers

| Header | Value | Description |
| --- | --- | --- |
| `Authorization` | `Basic <basic_token>` | Basic token generated from `/v2/auth/token` or `base64(public_key:secret_key)` |
| `X-MERCHANT-ID` | `<your_merchant_id>` | Master merchant identifier holding partner or marketplace credentials |
| `Content-Type` | `application/json` | Required for JSON request bodies |

### Optional Headers

| Header | Value | Description |
| --- | --- | --- |
| `X-SOURCE` | `API` / `SDK` / `CHECKOUT` / `PAYMENT_LINK` | Request origin source (Default: `API`) |
| `X-SOURCE-CHANNEL` | `web` / `android` / `ios` | Request channel platform (Default: `web`) |
| `X-BROWSER-FINGERPRINT` | string | Optional client browser fingerprint |
| `X-MERCHANT-APP-ID` | string | Optional merchant application identifier |

---

## 3. Request Body

The request must be sent in JSON format. The split configuration is passed inside `paymentHandler.oneSplit`.

### Core Fields

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `amount` | number | Yes | Total customer transaction amount in paise (1 INR = 100 paise). Range: 1 to 1,000,000 |
| `currency` | string | No | Currency code. Allowed: `"INR"`. Default: `"INR"` |
| `merchantOrderId` | string | Yes | Unique order ID from your system. Alphanumeric only (`^[a-zA-Z0-9]+$`) |
| `expireAfter` | number | No | Expiry time in seconds (300–900). Default: 300 |
| `customer` | object | Yes | Customer identity information |
| `paymentInfo` | object | Yes | Payment configuration and redirect details |
| `paymentHandler` | object | Yes | Handler configuration containing `type: "STANDARD"` and the `oneSplit` object |

---

### customer Object

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `name` | string | Yes | Full name of the customer (max 255 characters) |
| `email` | string | Yes | Valid email address (max 255 characters) |
| `phone` | string | Yes | Mobile number (max 15 characters) |

---

### paymentInfo Object

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `redirectUrl` | string | Yes | Valid URL where user is redirected after payment |
| `remark` | string | Yes | Transaction note or purpose (max 255 characters) |

---

### paymentHandler Object with OneSplit

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `type` | string | Yes | Must be `"STANDARD"` |
| `gateway_reference_id` | string | No | Optional custom gateway reference ID (max 255 characters) |
| `oneSplit` | object | Yes | The split configuration object defining sub-account allocation |

#### oneSplit Object Schema

| Field | Type | Required | Constraints | Description |
| :-- | :-- | :-- | :-- | :-- |
| `originpay_sub_acc_id` | string | No | Max 255 chars | The unique Originpay sub-account identifier where split funds are allocated. Cannot be empty if provided. |
| `remark` | string | No | Max 255 chars | Custom description, invoice reference, or reason for the split. |

---

## 4. Request Example

```json
{
  "amount": 75000,
  "currency": "INR",
  "merchantOrderId": "SPLIT987654321",
  "expireAfter": 600,
  "customer": {
    "name": "Jane Doe",
    "email": "jane.doe@example.com",
    "phone": "9876543210"
  },
  "paymentInfo": {
    "redirectUrl": "https://marketplace.example.com/checkout/callback",
    "remark": "Marketplace Order #SPLIT987654321"
  },
  "paymentHandler": {
    "type": "STANDARD",
    "gateway_reference_id": "GW_REF_4412",
    "oneSplit": {
      "originpay_sub_acc_id": "sub_acc_109283",
      "remark": "Vendor share for SKU #9912"
    }
  },
  "udf_vendor_id": "VEND_9912",
  "udf_invoice_no": "INV_2026_01"
}
```

## 6. Implementation Example

### JavaScript (Fetch)

```javascript
const requestBody = {
  amount: 75000,
  currency: "INR",
  merchantOrderId: "SPLIT" + Date.now(),
  expireAfter: 600,
  customer: {
    name: "Jane Doe",
    email: "jane.doe@example.com",
    phone: "9876543210"
  },
  paymentInfo: {
    redirectUrl: "https://marketplace.example.com/checkout/callback",
    remark: "Marketplace order payment"
  },
  paymentHandler: {
    type: "STANDARD",
    gateway_reference_id: "GW_REF_4412",
    oneSplit: {
      originpay_sub_acc_id: "sub_acc_109283",
      remark: "Vendor settlement allocation"
    }
  }
};

const response = await fetch("https://api.originpay.in/v2/onecheckout/pay", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "Authorization": "Basic YOUR_BASIC_TOKEN",
    "X-MERCHANT-ID": "YOUR_MASTER_MID"
  },
  body: JSON.stringify(requestBody)
});

const result = await response.json();
```

---

## Important Notes

- **Sub-Account Validity**: Ensure `originpay_sub_acc_id` corresponds to an active, registered sub-account linked to your master merchant ID.
- **Single Checkout Redirection**: The returned `payment_url` presents a single, standard checkout experience to the customer; the allocation to the sub-account is managed automatically on the backend upon payment capture.
- **Fee and Settlement Handling**: Originpay automatically calculates platform fees, gateway fees, and applicable taxes before posting the net split amount to the sub-account.
- **Verification via Status API**: When verifying the order via `/v2/order/command`, use the original `merchantOrderId` to fetch status and attempt history.
